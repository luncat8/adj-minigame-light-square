# findings, pitfalls, skills

- board corner cells (0,0), (0,14), (14,0), (14,14) can never be hit: light is absorbed by the first border cell it enters and border cells do not propagate, so a ray along row/col 1 never turns the final corner. Keep corners out of 0.3 receiver pools and 0.4 generation.
- diagonal reflection is a xor on dir (0=up, 1=right, 2=down, 3=left): `/` = dir^1, `\` = dir^3.
- corner-rule flips reduce to a closed form: corner on + quarter = flip every tile each move; corner on + single = flip iff from-slot mod (side-1) is 0 (cw) or 1 (ccw); corner off = never. Fixtures count flips instead of walking edges.
- a mirror loop cannot trap a ray seeded in its interior: cardinal rays cross loop edges through straight cells and escape. Closed loops only terminate rays that travel the loop itself (visited on enqueue); fixture seeds the loop path.
- cross-file constants: top-level const is visible to later classic scripts but not on window and not across node modules. Read sibling exports inside functions (lazy init) instead of at definition time — keeps load order free and files requireable alone.
- trace bound: visited bitmask per (cell, dir) at enqueue, ≤3 propagations per entry, union at receivers; queue Int32Array(4096) covers 169 interior cells.
- RING_CELLS indexes the 49-cell glass tile array, not the 15×15 board: glass cell = (row-4)*7 + (col-4). Map through GLASS_OFF before any hit test or tile read against board coordinates.
- trace buffers (traceRecv/traceSeg) are null until the first traceReset: alias them at call time (recvNow/recvBuf pattern), never at module load — generate.js fixtures pass because of this, a load-time alias crashes the first evaluate.
- canvas.width/height assignment resets the 2d context state: setTransform + lineCap/lineJoin/composite must be set every paint, not once at init.
- dom smoke without a browser: stub document/window/rAF before require('../app.js') and drive the real addEventListener handlers through a stored-handler fire(); it caught both a coordinate-space bug and a load-order-lazy bug that node --check cannot see.
- 0.5 band measurement (n=200 x 12 ruleset-band combos): fallback 0%, attempts med 1 max 6, witness hits 1-3 — sampled availability is not the difficulty lever; bands differ by quota/color policy, so slider labels state the policy (few/any, all/any, all/exact).
- classic scripts share one global lexical scope: two files declaring the same top-level const (e.g. the `gBoard` node-shim in game.js and generate.js) throws SyntaxError at load, so every later file's globals are missing and boot dies with misleading ReferenceErrors. require-based experiments cannot see this — they run each file in its own module scope. Keep node-shim consts prefixed per file (g* / i* / a* / r* / n*), and load all classic scripts into one `vm` context in `dom_smoke.js`.
- multiple render skins behind one dispatcher: two classic scripts cannot both declare the page-facing `renderInit`/`renderView`/… (same top-level name = load-time SyntaxError), so the dispatcher owns the public `render*` names and each skin exposes interface-named functions (`glass*`, `renderAlt*`). The dispatcher forwards every call to the active skin, stores the last view/selection, and on switch calls `stop()` on the old skin (cancel rAF + drop its resize listener) before `init()`-ing the new one and re-publishing the live view — a switch then loses no state and leaks no loop. Node module exports use different names than the skin interface, so the dispatcher maps them explicitly in its skin table.
- animated beam dashes without path stitching: traceSeg records outgoing directions per cell, so drawing full 1.0-cell center-to-center steps `(c+0.5, r+0.5) -> (c+0.5+dx, r+0.5+dy)` (plus the 1.0-cell emitter exit) puts every cell center and 90° mirror reflection at an integer arc-length from the emitter. A dash period dividing 1.0 (`0.5` = `[0.2, 0.3]`) with `lineCap = 'butt'` and negative `lineDashOffset` animates smoothly forward from emitter to target with zero phase jump at turns and zero additive cap hotspots at cell centers.
- canvas outer margin (`RIM_PAD`): shifting the board origin by `rCell * RIM_PAD` exposes `< 0` and `> BOARD_N` rim coordinates while keeping board drawing in `[0, BOARD_N]`; subtract `RIM_PAD` in `renderPointToCell` before `Math.floor`, and symmetric padding preserves `(width/2, height/2)` as the board center `(7.5, 7.5)` for angular ring drags.
- old prototype comparison (bc2bdf2, parallel src/ build of 0.1–0.6): its `sampleWinRate` — Monte-Carlo random walks (64 × 20 steps) scoring candidates against a target win rate from a continuous slider, best of 8 candidates — is a measured difficulty lever the band system replaced with quota/color policy. If a continuous dial is ever wanted, reuse that shape plus its separate scoring RNG stream (`seed ^ 0x9e3779b9`) so candidate sampling never perturbs scoring. Everything else it does (object-queue trace, per-move slot arrays and pose slices, edge-walk corner flips, per-mask 8-color beams, status strings per recompute) the current files already do allocation-free — no pickups.
- difficulty selection must compare like units: use one fixed-budget walk score across movement modes; keep bounded BFS as an exact-or-capped diagnostic, not an interchangeable score. Quarter-state upper bound is 1664; single-slot is 79872. Consecutive BFS dequeues need not be adjacent, so reconstruct each pose from its encoded turns or track an explicit pose cursor. A monotonic target does not guarantee monotonic generated puzzles; validate held-out averages and report saturation.
- exact mirror count is `(tile & 7) !== 0`, not `tile !== 0`; clear tiles should be zero. Sample occupied cells without replacement and masks from 1…7. Treat density separately from measured difficulty, and require fallback templates to preserve the requested count too.
- a catalog builder that validates through the page's own decoder can certify garbage: a decoder returning move objects while the consumer expected action ids replayed as emitter-only steps and every preset still "verified". Round-trip each encoded entry (decode == searched data) before validation, and assert semantic properties (preset replays through a ring move) in fixtures, not just `verifyCandidate`.
- `Math.ceil(h * frac)` with interpolated fractions overshoots: `20 * 0.65 = 13.000000000000002`. Use `ceil(x - 1e-9)` for quota-style counts.
- partial Fisher–Yates over a reused index buffer is uniform from any starting permutation, but not seed-reproducible unless the buffer is reset to identity each call.
- 0.8 exact-count generation is cheap: at 1/11/49 mirrors and every dial, fallback 0% and ≤2 attempts on average (n=100 per cell), so selection budget (step 3) can spend on walk scoring, not on candidate availability.
- ring turn tables for BFS: turning an all-mirror probe (every tile mask 7) beside an index array yields, per net turn, the source cell and the flip parity for each slot, since flips then depend only on slot path. One table pass rebuilds any pose; fixtures compare it against incremental `shiftRing` sequences.
- scramble length is a weak difficulty proxy (0.8 step 2, n=30 per cell, 11 mirrors): exact BFS minimum averages 1.4 / 2.6 / 3.1 moves (quarter) and 1.7 / 3.3 / 4.8 (single) at dial 0 / 0.5 / 1 against 3 / 8 / 14 scramble moves. Never label `solution.length` as par.
- single-candidate walk scores (dial 0.25: 0.65 quarter / 0.73 single) overstate what selection delivers: best-of-8 tracks the target within 0.02–0.08 at every dial. Calibrate the target on the selected output, not on raw candidates. One walk score costs ~0.9 ms in node, so 8-candidate selection is ~7 ms.
- 0.8 calibration (held-out, n=200/cell, count 11): target `0.20 + 0.80·d` gives independent 256-walk probe 0.22–0.23 → 0.96–0.99 across rulesets, monotonic, no overlapping adjacent dials. The old 0.85 ceiling capped dial 1 at exact par ≈2.8; ceiling 1 gives 5.2–6.2. Exact par stays 1.0–1.6 for dials 0–0.5 and rises mostly above 0.75: walk score is linear in the dial, move depth is convex. Counts 5/25/49 track the same way (probe 0.21–0.27 → 0.96–0.99), no saturation; generation p95 ≤ 18 ms in node at any count.
- `pgrep -f pattern` inside a `bash -c` wait loop matches the loop's own command line when the pattern appears in it, so the loop never ends. Wait on PIDs (`cmd & pid=$!; wait $pid`) instead.
- the walk score and BFS have one action order (ring r ccw/cw 0…5, center 6, emitter left/right 7–8). Deriving the emitter direction from the action's low bit gives left = +1 — keep emitter direction explicit.
- ring movement landmarks without touching `tiles`: `generate_fixtures` and `contractWon`/BFS expect clear cells in `puzzle.tiles` to remain `0`, so cell relief glyph indices live in a parallel `puzzle.glyphs` `Uint8Array(49)` (plus `GLYPH_CENTER_ALT` for center flips). Alternating scripts by `((floor(s / (side - 1)) + (s & 1)) & 1)` makes every even-stride quarter turn swap script on 100% of ring cells as well as swapping adjacent cells along each edge. Scaling the canvas text transform by `1/100` and drawing at `38px` avoids `<1px` CSS font shaping quantization on Devanagari conjuncts/matras while keeping `ctx.font` a zero-allocation constant string.
- recurring `requestAnimationFrame` handles must be reassigned inside the frame callback (`rRaf = requestAnimationFrame(rFrame)`), not only on `init()`: otherwise `cancelAnimationFrame(rRaf)` on a skin switch after frame 1 cancels a retired frame ID and leaks a second parallel loop.
- BFS event-depth monotonicity requires border cells to ride the FIFO queue at `depth + 1` rather than logging `EV_ABSORB` eagerly when the parent steps out: eager logging emits a fast straight branch's `depth + 1` border hit before already-queued `depth` interior steps.
- hot-loop V8 typed-array hoisting (`traceRun`): reading 11 mutable top-level `let` typed-array bindings and calling 8-arg helpers per BFS step added ~11% to `generate()` (`0.45 µs/trace`); hoisting local `const` array refs and scalar cursors inside `traceRun` kept full 5-kind event logging within `+3.6%..+4.6%` across `mirrors ∈ {1, 11, 49}`. Measure `generate()` deltas interleaved in one native V8 realm (`vm.createContext` slows cross-realm `shiftRing` ~10×, and separate OS runs drift ~15%).
- normalized stereo pan must be clamped to `[-1, 1]` before multiplying by stereo `width`: clamping after `* width` lets `(col + 0.5*dx - 7) / 7` at border cols `0`/`14` exceed `±width`. In Web Audio portamento voices (`Prism Pad`, `Comet`), track `curHz` and call `cancelScheduledValues(when)` + `setValueAtTime(curHz, when)` before `exponentialRampToValueAtTime` so events closer than `glide` never jump at stale ramp endpoints.

- audio params hang off nodes (`panner.pan`, `filter.frequency`), so node-stub probes must record on the param, not the node: a "silent" or pan-less voice in a probe is usually a wrong property read, not a dead graph. Read ramp chains from the param's event log (`lin` targets), and expect the final state after absorbs (voice count 0 is success, not a spawn failure).
- choice params in the variant schema (`choices` on a param) must bypass every numeric path: panel storage and rebuild validate by membership (`spChoice`), the audio resolver keeps the string, and `spClamp` would silently fall back to the default because `Number('absolute')` is NaN. `sound_smoke` asserts the select change and the storage round trip.
- Chromium click-anywhere audio unlock alongside a checked `<label><input type="checkbox">` must ignore events inside the wrapping `<label>`: clicking the label text dispatches an outer `click` on `<label>` *before* the browser synthesizes the inner `click` that flips `checkbox.checked` to `false`, so a naive document `click` unlocker sees `checked === true` and briefly starts audio when the user is unchecking it. Also keep calling `ac.resume()` on subsequent clicks whenever `ac.state === 'suspended'`, not only on the `auOn` `false -> true` edge.
- when a ray's very first glass interaction is `EV_SPLIT`, `note.dirOut` holds the *reflected* direction while passing channels continue along `dirIn = (note.dirOut + note.turn) & 3`; per-band voices spawned on that event (`Spectrum Drift`) must seed initial `band.dir` from `dirIn`, not `note.dirOut`.
- button moves schedule SFX *and* the harmonic bed synchronously (`soundRotate` before `refresh` -> `soundView` -> `auUpdateBed`), so osc-count/pitch probes measured after a button click mix SFX with bed oscs; measure SFX timbre via direct `fxRotate`/`fxLaser` calls and reserve button clicks for first-osc duration and `sfxBus` routing checks.
- a registered SFX voice lifetime must cover the *last scheduled* source, not the main one: an end settle at `0.92·dur` with its own `0.145` decay+margin outlives a `dur + 0.1` registration on short moves (rail end stop, single steps). Either compute the furthest `src.stop` across layers or scale late contacts with move duration (`min(0.11, dur * 0.45)`).
- positional per-cell render assertions can slice `fillStyles` deterministically: `drawGlass` fills `GLASS_BASE` once, then the 49 rotatable cells in row-major order, so one pumped frame's cells sit at `slice(indexOf(GLASS_BASE) + 1, +50)`. Count-based tint/shade checks stay skin-agnostic because tint strings exist only in the rotatable-cell fill path.
