# 0.5 · Play surface and controls

Draw a centered square board on black, with legible translucent glass, diagonal faces, luminous RGB paths and clearly separated border receivers. Preserve the centerline of a thin beam even with glow. Show the selected ring before moving it. Treat laser width as a physical footprint, not merely stroke thickness.

- Wheel over a ring steps it clockwise/counterclockwise; dragging along its perimeter accumulates signed slot steps. Lock the selected ring for the gesture. Provide explicit step buttons for touch/keyboard, including the singleton. Drag the emitter or use left/right controls.
- Keep percentage and mismatch feedback beside the board. Provide individual live-match and discovery toggles, a target reveal, restart, preferred difficulty slider and Generate. Changing preferred difficulty alone does not replace the current puzzle.
- Proposed solution control: hold (or hover with a pointer) to view the saved solved board **and** laser position; release, leave or cancel restores the player's exact pose. Preview never records discoveries or triggers a player win. Genuine completion leaves the solved board visible until the player chooses Generate.

**Integration:** open index.html via file://, using ordered classic local scripts, no build or network dependency. Separate board moves, tracing, goals, generation, drawing and controls by owner; the composer only wires them together. Keep rule logic DOM-free for Node fixtures.

**Acceptance:** manual pass on mouse and touch: generate, slide laser, move each ring both ways, inspect split colors, reveal a target, preview and cancel mid-puzzle, win and generate again. Confirm scrolling outside the board still works, resizing retains square cells, and preview/hints do not mutate progress. Run the shared integration smoke after wiring.
