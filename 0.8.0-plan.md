# 0.8 · Sparse mirrors and measured difficulty

## Goal and scope

Generate human-readable light puzzles on a 7×7 glass area with two independent controls:

- **Mirrors:** an exact integer count, displayed as `11/49`; default **11**.
- **Difficulty:** a 0–100 dial; default **25**. Higher settings seek puzzles that are
  harder to solve by short legal move sequences, without adding mirrors.

The board has four movable rings (including a flippable center), a white emitter with
columns 1–13, colored reflective tiles, and absorbing border receivers. Contracts specify
receiver requirements, a match quota, and optionally prohibit light outside the targets.
A generated puzzle includes a winning witness pose and a replayable legal solution from
a non-winning start. Keep those rules, hint/discovery behavior, preview, and rim feedback.
No sound, optical-rule changes, persistence, build system, or dependency is in scope.
Use local classic scripts and support both `file://` play and Node fixtures.

## 1 · Exact mirror count

### Representation and sampling

A tile's low three bits are its reflective RGB mask; bit 3 selects `/` or `\`.
A **mirror** has `(tile & 7) !== 0`; a clear cell is exactly `0`. A mask reflecting all
three channels still counts as one mirror. A diagonal-only value is not a mirror and
must not be produced for a clear cell.

`randomGlass(rng, mirrorCount)` in `generate.js`:

1. Start with 49 clear cells and a reusable index buffer containing 0…48.
2. Partially Fisher–Yates shuffle the first `mirrorCount` indexes, drawing without
   replacement. Select exactly that many cells, uniformly over subsets.
3. Give each selected cell a uniform nonzero mask 1…7 and an independent diagonal bit.
4. Return the tiles; no retry loop for occupancy, and no forced occupied center or ring.

Accept integers **1…49**. Zero is deliberately excluded: an empty board has no useful
ring puzzle. Reject invalid programmatic counts with `RangeError`; DOM controls normalize
finite input to a rounded, clamped integer, restoring 11 for blank/nonfinite input.
The count is independent of the dial, mode, corner rule, and sampling profile. Ring moves,
center flips, scrambling, Restart, and Preview must preserve it. Do not quietly substitute
a dense board or a one-mirror puzzle when generation is difficult.

### Count-preserving fallback

Use a small local preset catalog keyed by `(mode, corner, mirrorCount)`, covering all
196 combinations. Templates use only white mirrors (mask 7): each witness lights one
receiver, and its start lights a different receiver. Each template stores the witness's
occupied cells and diagonals, emitter, and a short legal forward scramble. Derive the
start and inverse solution from this data; do not store duplicate full poses.

Produce the catalog once with a deterministic development-only search; commit the compact
fixture data, not an unbounded search in the page. Verify every entry before accepting the
catalog, including count 49. A witness with one receiver and a start missing that receiver
supports either an any-color or exact-color contract with quota 1. Thus every difficulty
profile can use the same count-specific template. No nearby-pose pool enlargement is used.
If compact templates cannot meet these invariants for a key, resolve that before shipping;
never silently relax the count or validity requirements.

Fallback is explicitly marked `preset: true` and shown as `preset · difficulty not matched`.
It guarantees a valid puzzle, not the requested difficulty. Difficulty measurement may be
omitted for a forced or exhausted-budget fallback; show `not measured`, not an invented score.

## 2 · Generator inputs, outputs, and reproducibility

Public entry point:

`generate(seed, mode, corner, difficulty, mirrorCount = 11, opts = {})`

- `seed`: unsigned 32-bit value; `difficulty`: finite number clamped to 0…1.
- `opts.maxAttempts = 400`, `opts.candidateCount = 8`; attempts are shared across the
  entire call, not reset for each candidate. Zero attempts forces the catalog fallback.
- Each attempted candidate samples exactly the requested count, derives a contract from
  the witness hits, legally scrambles the witness, and replay-verifies the result.
- Verification requires byte-identical witness tiles and emitter after replay, a winning
  witness, a non-winning start, and the requested count in both poses.
- Stop after eight verified candidates or the attempt limit, then select the best verified
  candidate. If there are none, return the verified count-specific preset.

Retain candidate fields `mode`, `corner`, `start`, `startEmitter`, `witness`,
`witnessEmitter`, `contract`, `solution`, `preset`, and `witnessHits`. Add `seed`,
`difficulty`, `mirrorCount`, `attempts` (total attempted), `verifiedCandidates`,
`selectionScore`, `targetScore`, and measurement metadata. Scores are nullable when not
measured. `solution.length` is a verified upper bound, never labeled minimum moves.

Own the seed at this API boundary so independent streams are unambiguous:

- Candidate construction uses `makeRng(seed)` only.
- Measurement creates a fresh stream per verified candidate from
  `makeRng((seed ^ 0x9e3779b9 ^ Math.imul(candidateIndex + 1, 0x85ebca6b)) >>> 0)`.
- Measuring, displaying, or diagnostically searching a candidate never consumes the
  construction RNG, changes that candidate, or changes subsequent candidate construction.
- Candidate order, tie-breaking (earliest wins), counts, and scores are reproducible for
  the same inputs and budgets. Wall-clock time is reported, not used to select candidates.

## 3 · Dial → generation profile

`profile(difficulty)` is a pure function. Linearly interpolate the following anchors;
round integer fields to nearest integer. These are initial tuning values, not measured
claims about human difficulty.

| Dial | Quota fraction | Exact-color probability | Scramble moves | Eligible ring count |
|---|---:|---:|---:|---:|
| 0 | 0.50 | 0 | 3 | 1 |
| 1/3 | 0.65 | 0 | 6 | 2 |
| 2/3 | 0.85 | 0.50 | 10 | 3 |
| 1 | 1 | 1 | 14 | 4 |

For `h` distinct witness receiver hits, require
`quota = min(h, max(1, ceil(h * quotaFrac)))`. Each witness hit becomes a target;
independently choose its exact observed mask with `exactProb`, otherwise any color.
Only at difficulty 1 use the strict contract: all witness hits, all exact masks,
quota `h`, and no outside light. A zero-hit witness is rejected. Do not add receivers
that were not hit by the witness; this keeps validity and preset behavior simple.

Choose an eligible subset uniformly from all four rings per candidate, not always the
outer rings. This limits scrambling only; players and measurements may use every ring.
Choose ring moves with probability 0.8, emitter moves with probability 0.2, uniformly
among legal actions of that type. Skip immediate inverse moves during scrambling when
another action exists. Emitter steps remain within 1…13; draw the witness emitter from
4…10, the columns crossing the glass, at every dial value. Do not use emitter range as a
hidden difficulty rule. Require the requested number of actual legal scramble moves.

Scramble length and eligibility influence the candidate pool; they do not establish
shortest solution length or guarantee that every eligible ring matters.

## 4 · One comparable selection metric

Use the **same random-walk score in both movement modes**, regardless of state-space
size. Mixing BFS move depth and win-rate fractions would make candidate distances
incomparable, especially where a search crosses its budget.

For each verified candidate, run **64 independent walks of at most 20 legal moves** from
its start. Reset a scratch pose before every walk. At each step choose uniformly from
all legal actions: both directions on each non-center ring, one center flip (the two
center directions are identical), and in-bounds emitter steps. Unlike scrambling,
measurement walks allow backtracking. Stop a walk at its first winning pose.

`winRate = successfulWalks / 64`

`selectionScore = 1 - winRate` (larger means harder for this fixed probe).

Initially use `targetScore = 0.20 + 0.65 * difficulty`. Pick the candidate minimizing
`abs(selectionScore - targetScore)`. Keep walks, steps, and action policy fixed across
all dial values and counts so scores are comparable. Record successes and total walks
alongside the score; this is a coarse estimate, not a confidence-free human difficulty
rating. Candidate selection can improve averages; it cannot guarantee monotonic individual
puzzles, distinct results at every dial tick, or target attainability at every count.

All tracing and measurement use scratch poses, not the live puzzle or discovery history.
`traceLight` owns shared result buffers: consume each result before the next trace, and
never retain a receiver-buffer reference as a snapshot. Add an allocation-free
`contractWon(contract, recv)` predicate in `contract.js` for this hot loop; share its
quota/extras semantics with `evaluateContract`, and test their agreement. Reuse measurement
buffers and do not allocate status arrays per probe.

Worst-case normal selection is 8 × 64 × 20 = **10,240 traced measurement moves**, plus
candidate construction. Measure this cost before increasing candidate count or probes.
Do not promise unchanged generation time while adding this work.

## 5 · Exact shortest-path diagnostic (not selection)

A bounded BFS supplies honest minimum-move diagnostics and offline calibration. Put it
in `difficulty.js`, alongside random-walk measurement; generation remains in `generate.js`.
This separates substantial search machinery and keeps either file below roughly 500 lines.

- State: `(emitter, ringTurns[0…3])`, relative to the candidate's start.
- Quarter-mode periods: `4/4/4/2`; single-slot periods: `24/16/8/2`.
  With 13 emitter columns the upper bounds are **1,664** and **79,872** states.
  Fixtures must verify these periods under both corner settings, including diagonals.
- Encode states with mixed-radix integers; reuse visited/depth/queue buffers. Use the same
  legal action graph as measurement and count one legal ring or emitter action as one move.
- Reconstruct each dequeued state's scratch pose from the immutable start and decoded
  ring turns, or transform from a tracked cursor using legal shifts. Consecutive dequeued
  BFS states need not be adjacent: a move/inverse around the previous state is insufficient.
- Trace each visited pose once and test the real contract predicate. Stop at the first win.
- Default cap: **20,000 evaluated states**, not merely a state-space-size check. Return
  `{status: 'exact', moves, visited}`, `{status: 'capped', moves: null, visited}`, or
  `{status: 'unreachable', moves: null, visited}` only after exhaustive failure.
- Search never mutates candidate tiles, contract, solution, or the construction RNG.
  A cap is neither a loss nor an exact par value.

Run BFS in the development harness by default, not eight times during interactive
selection. If a shipped minimum-move readout is later desired, budget it separately;
it is not needed to complete this plan.

## 6 · UI and ownership

`index.html`, Generate fieldset:

- Replace the band control with a labeled `difficulty` range, min 0, max 100, step 1,
  value 25, and live `difficulty-label` showing `Difficulty 25/100`.
- Add labeled `mirror-count` number input, min 1, max 49, step 1, value 11; display
  `Mirrors 11/49` through `mirror-count-label`. Set title/help to explain that fewer
  mirrors reduce visual clutter and that difficulty does not change their count.
- Keep pending settings separate from the active-puzzle summary. Show active count,
  requested difficulty, and optionally `walk escape 38%` (the measured win rate).
  Do not expose minimum-move answers by default or imply the score measures human skill.

`input.js` owns control bindings and live pending-label updates; `game.js` owns reading
normalized generation settings, making the seed, calling the generator, and displaying
active metadata. Avoid globals colliding with DOM ids; update Node exports and test stubs.
All settings, including mode and corner rule, apply **only on Generate**. Editing a control
does not retrace, change the active puzzle, clear discoveries, or end a preview. Restart
restores the active start; Preview shows its matching witness, not pending settings.

Ownership additions:

- `difficulty.js`: owns fixed-budget walk scoring and bounded BFS diagnostics; guarded
  Node exports and collision-free classic-script names. Load after `contract.js`, before
  `generate.js`; no definition-time cross-file reads.
- `presets.js`: owns compact count-preserving fallback templates; pure lookup/data only.
  Load before `generate.js`.
- `experiments/build_presets.js`: deterministic catalog construction and validation.
- `experiments/difficulty_fixtures.js`: metric, predicate agreement, BFS and isolation tests.
- `experiments/difficulty.js`: seeded sweeps and fixed-key metric output.
- `experiments/compare.js`: keyed report comparison.

Update the ownership map in `AGENTS.md` when implementing. Keep `app.js` a composer.

## 7 · Calibration and performance evidence

Use deterministic seed lists, held-out seeds for acceptance, and identical budgets for
comparisons. Initial sweep: both modes × both corner settings × counts `{5, 11, 25, 49}`
× dial `{0, .25, .5, .75, 1}`, at least 200 puzzles per cell. Exercise counts 1…49
in validity/catalog tests even where a useful difficulty range is unavailable.

Emit whitespace-separated `key=value` records, one line per aggregate, with no spaces
inside values. Include `mode`, `corner`, `mirrors`, `difficulty`, `samples`, `score_avg`,
`score_se`, `target_error_avg`, `par_exact_avg`, `par_exact_n`, `par_capped_n`,
`solution_len_avg`, `gen_ms_avg`, `gen_ms_p95`, `attempts_avg`, and `fallback_rate`.
Use `na` for absent exact-par data; never average capped searches as if solved.

Estimate independent walk success on the selected puzzles with a separate diagnostic
seed stream; do not validate selection using only the same walks that chose the winners.
BFS calibration may use a documented fixed subset if the full sweep is too expensive.

At count 11, require nondecreasing mean held-out difficulty within sampling uncertainty
and an easy-to-hard increase of at least 0.10 in independent walk score for each ruleset.
Report overlapping adjacent levels instead of claiming they are statistically distinct.
Report saturation at other counts; density is a readability control, not a monotonic
solver-difficulty scale. If targets cannot be reached, tune anchors or target range on
training seeds and rerun held-out evaluation; do not relabel failed results as calibrated.

`compare.js` joins matching keys, reports missing cells, absolute deltas for scores and
rates, relative deltas for positive timing/count metrics, and configurable thresholds.
A 5% timing change is a review flag, not proof of significance. Initial interactive
performance goal: generation p95 ≤250 ms on the documented test machine at count 11;
record browser/device results separately. If it fails, explicitly revise work budgets or
schedule bounded work between frames with Generate disabled; do not ship a frozen page
or make reproducibility depend on elapsed milliseconds. Keep decision-producing raw logs
under `experiments/logs/`; summarize calibration and limitations in findings.

## 8 · Acceptance and validation

Automated:

- Default generation produces exactly 11 mirrors; all 49 allowed counts are exact in
  witness, start, replay, Restart, and Preview. Counts 1, 11, and 49 have focused fixtures.
- Clear cells are zero; selected masks are nonzero; sampling is deterministic and can
  place mirrors on every cell without duplicates. Invalid API inputs fail as specified.
- Across modes, corner settings, representative dials, and forced fallback, all returned
  candidates replay exactly, witnesses win, and starts do not. Catalog coverage is complete.
- Profile endpoints/interpolation, quota bounds, strict endpoint, legal scrambles,
  candidate/attempt limits, partial candidate batches, deterministic ties, and preset
  metadata are tested. No fallback silently changes count or claims a target match.
- Walk reset, bounds, center-action deduplication, RNG isolation, and nonmutation are
  tested. `contractWon` agrees with evaluation for any-color, exact, quota, and extras cases.
- BFS finds known 0/1/2-move minima, exhausts quarter-state graphs where needed, reports
  caps honestly, and preserves input. Test both modes and both corner settings.
- Seeded held-out sweep meets the count-11 calibration gate, reports saturation and
  fallback rates, and records timing evidence. Default-count fallback rate goal: <1%.
- DOM smoke covers pending vs active labels, count normalization, Generate, Restart,
  Preview, and all scripts loaded in a shared classic scope. File loading stays local.

Manual pass:

1. Open through both `file://` and an HTTP preview; default controls read 11/49 and 25/100.
2. Compare 5, 11, and 49 mirrors: sparse boards are visibly clearer; count matches the UI.
3. Change count/difficulty while playing and previewing; only Generate applies them.
4. Generate easy/hard puzzles at 11 mirrors in both movement modes and both corner rules;
   assess readability and actual solving feel, not just solution length or probe score.
5. Restart, solution Preview, hints/discoveries, emitter controls, and rim feedback remain
   correct; forced presets preserve count and communicate unmatched difficulty honestly.
6. Observe responsiveness during repeated dense/hard generation; record device and timings.

## 9 · Implementation sequence

1. Exact-count sampler, explicit settings API, and verified complete preset catalog;
   focused generation fixtures. Do not expose count UI before fallback respects it.
2. Shared allocation-free win predicate, walk scorer, and independent diagnostic BFS;
   focused predicate/search/isolation fixtures.
3. Profile and bounded candidate selection with metadata; generator acceptance fixtures.
4. Controls, pending/active readouts, bindings, script order, and ownership map; full Node
   fixture suite plus classic-scope DOM smoke because boot/load order is touched.
5. Training/held-out calibration, performance evidence, and manual pass; tune declared
   constants only with recorded results. Record implementation evidence in
   `archive/0.8.0-worklog.md`, not in this design document.
