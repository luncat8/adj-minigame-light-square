# 0.9 · Two renders behind a skin switch

Base: the 0.1–0.6 backend game (board, trace, contract, difficulty, hints, presets,
generate, rim, game, input) and its single canvas render. This plan makes the render
an **optional, switchable skin** and ships **two skins** over the same backend: the
existing **glass** skin and a new **prototype** skin adopted from the old prototype
(`f286079`) render, updated to the current view model and given the 0.6 rim items.

## decision: one page, not two

The two visuals live in **one `index.html`** behind a **Look** control, not in a
second page. The backend game, its view model, the panel and the boot are shared, so a
second page would duplicate markup, controls and wiring while splitting one source of
truth. One page with a switch keeps a single load order and lets the visuals be
compared live at runtime. The skin is optional: the default stays the current glass
look, and switching is a runtime choice that never changes the puzzle or progress.

## skin model

A **skin** renders the view model the backend already publishes
(`{ tiles, emitter, seg, recv, overlays, result, previewing }`) and owns its own
canvas sizing, painting, hit-testing and selection. The skin interface is five
functions:

- `init(root)` — bind canvas/context, size, start the skin's frame loop, add resize.
- `view(v)` — store the published view refs.
- `select(ring)` — store the active ring outline.
- `point(x, y)` — map a pointer to a board cell (or `null` in the rim margin).
- `stop()` — cancel the frame loop and remove the resize listener.

**`skins.js`** owns the active skin and the four page-facing entry points the rest of
the app calls (`renderInit`, `renderView`, `renderSetSelection`, `renderPointToCell`).
It forwards each call to the active skin, remembers the last view and selection, and on
`skinSelect(name)` stops the old skin, inits the new one and re-publishes the live view
so a switch loses nothing. `app.js`, `game.js` and `input.js` call the dispatcher in
both browser and node; they never name a skin directly.

Skins expose **interface-named** functions (`glass*`, `renderAlt*`). The page-facing
`render*` names live only in `skins.js`: two classic scripts declaring the same
top-level function collide at load (one shared lexical scope), so the dispatcher owns
the public names and the skins keep private ones.

## the two skins

**glass** (`render.js`) — the current look: sharp glass region, flowing dashed RGB
beams, circular targets, square current badges, diamond discovery dots. Unchanged
behavior; only its public functions are renamed to the skin interface and it gains
`stop()`.

**prototype** (`renderAlt.js`) — adopted from the old prototype render and retargeted
to the current view model: rounded per-cell glass, solid additive glowing beams,
diamond targets, rounded current badges. It **adopts the 0.6 rim items** by calling
`rim.js`'s `drawRimItems` in the same `RIM_PAD` coordinate space, so boiler, lamp,
billboard, crystal, detector, power cell and emitter rail, plus the receiver wiring,
appear in both skins. Hint overlays (targets/current/discoveries), the laser device,
selection outline and the PREVIEW tag follow the current model; the numeric readout
stays in the HTML for both skins.

Both skins share the rim margin geometry (`RIM_PAD = 1.5`, span `N + 2·RIM_PAD`) so
`drawRimItems` lands in the same margin and pointer hit-testing is identical across
skins.

## panel

A **Look** fieldset with a `<select id="skin">` (`glass` default, `prototype`).
`skins.js` binds its `change` event to `skinSelect`. No other control changes.

## validation

- L0: `node --check` on `render.js renderAlt.js skins.js app.js game.js input.js`.
- L1: `node experiments/skin_fixtures.js` — boots the page, pumps the glass skin,
  switches to prototype, asserts it paints, adopts rim items and hit-tests, switches
  back, and rejects unknown skin names.
- L2: full fixture suite (load order changed) — `move_fixtures`, `trace_fixtures`,
  `contract_fixtures` (script list updated to 14), `generate_fixtures`,
  `difficulty_fixtures`, `dom_smoke` (classic-scope vm loads all 14 scripts).

Manual pass:

- open `index.html` via file://, confirm the glass look is unchanged by default.
- switch Look to prototype: rounded glass, solid glowing beams, diamond targets, rim
  items and wiring all present; percentage and feedback readouts unchanged.
- move rings, drag the emitter, toggle hints and hold Preview in both skins; the board,
  progress and item states behave identically.
- switch skins mid-puzzle and mid-preview; the live view is preserved and restored.
