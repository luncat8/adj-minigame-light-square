# 0.4.0 solution preview

Base: groups, modes, panel, hints.

## behavior

The panel gains a `Hold: solution` button and a `Hover preview` checkbox. The checkbox is off by default. Holding the button previews the witness state: the laser moves to `solutionLaser` and every ring rotates to `solutionTurns`. Releasing restores the exact pre-preview state. The preview is read-only: it never changes `found`, never counts as progress, and never starts a new puzzle.

The `S` key is the keyboard equivalent: hold to preview, release to restore.

Hover preview is optional; hold is the default because hover reveals can fire accidentally. `Game.settings.hoverPreview` is false by default; `UI.sync` shows the checkbox state.

## state

`Game.preview` is a boolean. `Game._saved` is a preallocated object:

- `laserCol`, `laserWidth` — numbers.
- `turns` — array of four numbers.

`Board.create` initializes `b.preview` to false.

`Game.previewStart()`:

1. If already previewing, return.
2. Copy `laserCol`, `laserWidth`, and `rings[r].turns` into `_saved`.
3. Set `b.preview = true`, `Game.preview = true`.
4. `Board.applyTurns(b, b.solutionTurns)`.
5. Set `b.laserCol = b.solutionLaser`, `b.laserWidth = b.solutionWidth`, `Board.updateLaser(b)`.
6. `Game.refresh()` traces, refreshes status, and skips `found` updates because `b.preview` is true.
7. `UI.setPreview(true)`.

`Game.previewEnd()`:

1. If not previewing, return.
2. `Board.applyTurns(b, _saved.turns)`.
3. Restore `laserCol`, `laserWidth`; `Board.updateLaser(b)`.
4. `b.preview = false`, `Game.preview = false`.
5. `Game.refresh()` traces and rebuilds the normal status.
6. `UI.setPreview(false)`.

`Board.applyTurns` uses the shortest signed delta modulo the ring period, so restore takes at most half a cycle per ring. Cell objects are permuted, not copied; the grid returns to the exact pre-preview arrangement.

`Board.refreshStatus` skips `found` updates while `b.preview` is true. The pre-preview `found` array is therefore preserved without a copy.

## input

`ui.js` binds the button and window key events:

- `pointerdown` -> `previewStart`; `setPointerCapture` so `pointerup` arrives.
- `pointerup`, `pointercancel` -> `previewEnd`.
- `pointerenter`/`pointerleave` -> preview start/end only when `Hover preview` is on and no pointer button is held.
- `keydown` `KeyS` -> `previewStart` when the event target is not an input, textarea, or select; `keyup` `KeyS` -> `previewEnd`.
- `window.blur` -> `previewEnd`.

`Game.handlers.canInteract()` returns `!Game.preview`. `Input.onDown`, `onMove`, and `onWheel` ignore board input while previewing. `Input.onKey` handles `KeyN` before the guard; A/D and width keys are ignored while previewing. `KeyN` still works because `Game.newGame` calls `previewEnd` first.

`Game.newGame`, `Game.setMode`, and `Game.setFlipAtCorners` call `previewEnd` first.

## render and status

While previewing, the renderer draws a `SOLUTION PREVIEW` banner and the status line reads `SOLUTION PREVIEW   100%   release to restore`. The solution button gets an active class. On restore, the banner and active class clear and the normal status returns.

The preview shows the solved laser position and the solved ring positions. It does not show a move list; the player can inspect the board.

## edge cases

- New game or mode/corner change during preview: restore first, then apply the change.
- Window blur or pointercancel: restore.
- Pointer leaves the button while held: keep preview until pointerup (capture).
- Hover preview on, pointer leaves: restore.
- Preview when the start is already solved: generation rejects solved starts, so this cannot occur; the preview still works if a solved board is loaded.

## validation

L0: `node --check js/board.js js/ui.js js/input.js js/main.js js/render.js`.

L1: `node experiments/engine_smoke.js`, extended:

- `applyTurns(start, solutionTurns)` solves.
- save/restore returns the exact grid, laser column, width, and found array.
- `refreshStatus` during preview leaves `found` unchanged.
- shortest-delta restore uses at most half a cycle per ring.

L2: `node experiments/dom_smoke.js`, extended to dispatch pointerdown/up on the solution button and keydown/up `KeyS`; assert the board is restored.

Manual pass:

- hold the button; board jumps to the solution; release; board returns exactly.
- hold `S`; same.
- enable hover preview; hover in/out; preview/restore.
- start a preview, press `N` or switch mode; preview ends and the new state is clean.
