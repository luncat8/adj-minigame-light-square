# 0.4 · Solvable generation and difficulty

Use the move model (0.1), tracer (0.2) and win predicate (0.3) unchanged. Freeze corner behavior and emitter width per puzzle; changing either starts a new puzzle rather than invalidating its guarantee.

1. Sample glass and a solved pose, trace it, then derive requirements from real receiver hits. For strict tasks use the entire lit set and exact masks. For easy tasks choose a positive quota supported by actual hits and optionally enlarge the eligible pool. Reject empty or trivial contracts.
2. Scramble from that witness using legal reversible moves. Reject starts already satisfying the task. Retain the witness and inverses of the scramble; replay from the start and require a win before offering the puzzle. The witness need not be unique or shortest.
3. Bound generation attempts. If a requested difficulty band is unavailable, prefer the closest validated candidate; if none qualify, use a replay-verified preset for the active rules. Never label an unchecked random board solvable.

The slider targets *average* difficulty, not a guaranteed move count. Scramble length is not a difficulty measure: another emitter position may win immediately. In Node experiments sample seeds per width, corner mode and slider band. Measure the fraction of sampled poses that win, shortest depth on a bounded search subset (unreached is unknown), target count, rejection rate and generation latency. Choose bands with decreasing sampled win rates, then playtest whether extra search feels harder or just more tedious.

**Acceptance:** replay witnesses across seeded batches and all rule settings; zero invalid witnesses or already-won starts, including forced fallback. Report measured ranges before assigning slider labels. Manually compare several low/high pairs without peeking.
