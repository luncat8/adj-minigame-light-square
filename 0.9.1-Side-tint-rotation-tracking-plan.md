# 0.9.1 · Side tint rotation tracking

## goal

In quarter-turns mode the rotatable 7×7 cells stop reading as per-cell random glass
brightness (`CELL_SHADE`) and instead fill with one tint per side of each rotatable
ring, so a quarter turn visibly carries each side's color strip onto the next side.
Single-slots mode keeps the per-cell shade. Both render skins adopt the same data and
behavior.

## data (board.js)

`CELL_SIDE` (`Uint8Array(50)`) maps every cell identity to a tint group. Each ring's
`RING_CELLS` slots split into four contiguous strips of exactly `side - 1` slots — the
quarter-turn stride — so strip `b` always lands on strip `b + 1` under a quarter turn
in either direction. Strip 0 starts at each ring's top-left corner (top row minus the
far corner, so each strip is one geometric side plus the corner at its
counterclockwise end). The center cell and its `GLYPH_CENTER_ALT` flip glyph form
group 4. Tint is looked up through `glyphs[gi]` (tile identity), which `shiftRing`
already permutes, `restartPuzzle` already restores and the witness preview already
replays — so the strips rotate with the tiles and survive moves, restart and preview
with no extra state.

## view (game.js)

`publishView` adds `v.sideTint = live.puzzle.mode === MODE_QUARTER`. Skins treat it as
a rendering flag like `previewing`; they never read puzzle state directly. The witness
pose shares the puzzle's mode, so preview shows the rotated strips too.

## skins

- glass (`render.js`): `rGlassTints` — ember red strip 0, moss green strip 1, cobalt
  strip 2, amber strip 3, neutral glass center. One hue palette shared across rings:
  "which color sits on which side" stays learnable across puzzles, and any ring's turn
  shows as a color break against its neighbors.
- prototype (`renderAlt.js`): the same groups with slightly stronger alphas to match
  its brighter shade family.
- `sideTint` false (single slots) falls back to the existing per-cell shade lookup,
  including the per-puzzle `shadeOff`.

The color-to-side mapping is fixed in quarter mode (no `shadeOff` rotation) so the
association between a hue and a side stays stable and learnable.

## validation

- L0 `node --check` on `board.js game.js render.js renderAlt.js`.
- L1 `move_fixtures` (strip invariants: quarter stride maps group b onto b+1, center
  group 4) and `skin_fixtures` (four side tints + one center tint painted, 12 rotatable
  cells per side tint, one outer CW quarter rotates the strips onto the next side while
  inner rings hold, single-slots mode restores per-cell shade variety).
- L2 full suite — board.js is shared, so all nine fixture/smoke scripts run.

Manual pass: quarter mode — turn each ring CW/CCW and confirm strips travel with the
tiles and read clearly on both skins; Restart and Preview (hold) restore or rotate the
tints correctly; single-slots mode still shows per-cell brightness; hue contrast stays
comfortable against beams, mirrors, glyphs and hint overlays.
