# 0.1.1 ring modes and 1x1 flip

Base: 15x15 board, four concentric rings (7x7, 5x5, 3x3, 1x1), mask-based beam trace, canvas render.

## board

`Board.mode` is `quarter` or `shift`. `Board.flipAtCorners` is a boolean. Both are fixed when a puzzle is generated. The settings panel exposes them; changing either starts a new puzzle.

`Board.rings[r]` owns `size`, `slots`, `turns`. `turns` counts player inputs in the active mode: quarter turns in `quarter`, single-slot shifts in `shift`, flips for the 1x1 ring. `Board.period(ring)` returns 4 for quarter rings, `slots.length` for shift rings, and 2 for the 1x1 ring.

## quarter mode

One rotate input advances a ring by `slots.length / 4` slots (90°). Four inputs return every ring with slots to its original cell order and diagonals. Each input flips the diagonal of every moved cell.

## shift mode

One rotate input advances a ring by one slot. `slots.length` inputs return the ring to its start: 8 for 3x3, 16 for 5x5, 24 for 7x7. A shift moves cell objects without changing diagonals, except for the corner rule.

## corner rule

A one-slot shift is not a rigid rotation, so the diagonal cannot be derived from the shift alone. `flipAtCorners` resolves this: when a shifted cell enters a corner slot, its diagonal flips. Corner slot indices are `0`, `size - 1`, `2*size - 2`, `3*size - 3`. A full cycle enters four corners, so four flips restore every diagonal and the full cycle is the identity. With the rule off, shift mode is a pure cyclic permutation.

Quarter mode ignores the rule: every 90° input flips every moved cell once.

## 1x1 ring

The 1x1 ring has no slots. One rotate input flips the center mirror diagonal (`diag ^= 1`); two inputs restore it. This is the same in both modes. A generated puzzle's center cell is a mirror, so the move always has an optical effect.

## input

Pointer and wheel input call `Game.rotate(ring, dir)`, which calls `Board.rotateRing(ring, dir)`. `Board.rotateRing` reads `mode` and `flipAtCorners` from the board; callers do not branch on mode.

Drag threshold stays 0.35 rad per input. In shift mode one threshold crossing is one slot; in quarter mode it is one 90° turn. A wheel notch is one input.

The 1x1 ring flips on pointerdown and does not start a drag. Wheel over the center cell also flips it.

## state and solution

`Board.rotateRing` updates `rings[r].turns` by `dir` in mode units. `Board.startTurns` and `Board.solutionTurns` use the same units.

`Board.applyTurns(b, turns)` rotates each ring by the shortest signed delta from its current `turns` to the target, modulo the ring period, then sets `rings[r].turns` to the target value. The delta changes the cell arrangement; the assignment only changes the counter representative. Generation, solution preview, and tests all use this one path, so a save/restore cycle returns the exact counter values and the exact cell arrangement.

`Board.normalizeTurns(b, turns)` reduces entries modulo the ring periods for display and tests.

## generation

Generation accepts a settings object with `mode` and `flipAtCorners`. It chooses solved ring positions in the active mode, scrambles each ring by `1..floor(period/2)` inputs with a random direction, and stores the solved positions as `solutionTurns`. The 1x1 ring is included in scramble and solution. The center cell is forced to be a mirror with a random diagonal and a random reflect mask.

The start state is the scrambled state. `applyTurns(start, solutionTurns)` is the witness solution. Generation rejects a start that is already solved. Target selection stays the base exact-target list; 0.2.0 replaces it with groups and difficulty.

## settings panel

`index.html` adds a fixed `#panel` over the canvas. `js/ui.js` owns its DOM refs and events. The panel has:

- `Rotation`: `90°` and `1 cell` buttons.
- `Flip at corners` checkbox.
- `New puzzle` button.

The panel sits top-right over the canvas, uses the dark canvas palette, and wraps on narrow screens.

`UI.init(handlers, settings)` binds controls and calls `UI.sync(settings)` to show the active mode and checkbox state. `Game.settings` starts at `{ mode: 'quarter', flipAtCorners: true }`. `Game.setMode` and `Game.setFlipAtCorners` update settings, sync the panel, and start a new puzzle. `Game.newGame` passes settings to generation. `Game.start` calls `UI.init(Game.handlers, Game.settings)` before `Game.newGame`.

`index.html` load order: board, optics, render, input, ui, main. AGENTS.md file map gains `js/ui.js — owns settings panel controls. edit for panel layout, control wiring.`

## render and status

Status text includes the mode: `mode 90°` or `mode cell`. Ring geometry is unchanged; the renderer draws cell contents from the grid. The center mirror is drawn like any mirror, so a flipped diagonal is visible.

## validation

L0: `node --check js/board.js js/input.js js/ui.js js/main.js`.

L1: `node experiments/engine_smoke.js`, extended:

- quarter mode: four rotations of each ring restore the exact grid and diagonals.
- shift mode: `slots.length` shifts restore the exact grid; one shift changes the grid for rings with more than one slot.
- corner rule on: a shift into a corner flips the moved cell's diagonal; a shift out of a corner does not; off: no shift flips.
- 1x1: one flip toggles the center diagonal; two restore it.
- generated puzzles in both modes: `applyTurns(start, solutionTurns)` solves the witness; mode and flipAtCorners are stored.

L2: `node experiments/dom_smoke.js` after the panel exists; the DOM mock gains the panel elements.

Manual pass:

- wheel and drag each ring in both modes; count inputs for 360°.
- click and wheel the center cell; diagonal flips.
- switch mode or corner rule; a new puzzle starts; status shows the mode.
