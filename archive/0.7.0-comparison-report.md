**Sound plan review** — the plan is solid, but comparing it against the current trace internals I found four concrete gaps:

1. **No branch identity** — Prism Pad and Comet are defined "per branch" (sustained voices, diverging splits), but the event log and score carry nothing identifying which ray an event belongs to. Merges make it underivable at sonify time; it must ride the queue entry like depth.
2. **`time` baked into the score** — but `snd-speed` is a live setting, and the event log is overwritten by the next trace, so a speed change could never re-map. Notes should carry `depth` and the scheduler derive seconds.
3. **`publishView` is shared by moves and hint republish** — routed straight to `soundView`, a hint checkbox toggle would launch a full wave. Buffer identity never changes in place, so sound can't infer a pose change; it needs an explicit `moved` flag.
4. **Redundant sort** — the plan's own BFS argument already proves nondecreasing depth.


## Prototype vs current (bc2bdf2 `src/` ↔ root files)

The prototype is an independent reimplementation of the same game; most of it is what the current files already do, just allocation-heavy:

- **trace**: object queue + 3 fresh buffers per call → current packed `Int32Array` queue with enqueue-time dedup. Current wins.
- **movement/board**: `ringSlots()` + pose `.slice()` per move, edge-walk corner flips → current precomputed `RING_CELLS` + closed-form corner rule. Current wins.
- **render**: per-mask 8-color alpha beams → current per-channel additive + animated dashes. Same outcome, current cleaner.
- **input**: slot-tracking drag → current angular drag around the board center (matches ring geometry). Current wins.
- **rim items / composer**: per-cell trace-reading items, status strings per recompute → current aggregate contract-state items, persistent view object. Current wins.

**The one real pickup**: `sampleWinRate` — Monte-Carlo random walks scoring candidates against a *measured* target win rate from a continuous difficulty slider, with a separate scoring RNG stream so sampling never perturbs scoring. The band system deliberately replaced win-rate with quota/color policy (0.5 findings), so I recorded it in `findings-pitfalls-skills.md` as the shape to reuse if a continuous difficulty dial is ever wanted — not implemented now.

## Sound plan improvements (0.7.0-plan.md)

Reviewing the plan against the actual trace internals found four gaps, now fixed:

1. **Branch ids** — Prism Pad and Comet are defined "per branch", but nothing in the event log identified a ray. Branch now rides the queue entry next to depth (bits 23–30): seed 0, children inherit, split keeps the parent's branch on the continuing ray and gives the diverging ray a fresh one → `traceEvBranch`.
2. **Depth-carried time** — score notes now carry `depth`/`cell` instead of baked seconds; the scheduler derives `waveStart + depth/speed`. The live speed slider applies instantly, no re-sonify (the event log is reused by the next trace, so baked `time` could never be re-mapped). Also drops the sort the plan no longer needs — depth is nondecreasing by the plan's own BFS argument; fixtures now assert order instead.
3. **`view.moved` wave gating** — `publishView` serves both moves and hint republish, and buffer identity never changes in place, so a hint checkbox would have launched a full wave. Now: `moved` true from refresh/preview-start, false from republish — hint toggle retints bed + next wave only. Also pinned down: waves own their score snapshot (retints shape the next wave), loop timers die with the wave (covers generate/restart), `soundView` lives in audio.js and derives preview/won transitions itself.
4. **Spec precision** — bend/bounce propagation mechanism (parent → `propagate` → `traceSeed`, first-parent-wins on merge), `traceEvInfo` typed `Uint16Array` (13 bits), fixture additions for branch fork, merge determinism, republish-no-wave.
