# 0.8 · Comparison — old prototype f286079 vs current

`f286079` is an earlier iteration of the same ring-glass / emitter game, before the
contract + rim + replay-verify rewrite. Its gaps are expected of a prototype and are
not tallied here; the point is to surface approaches worth carrying forward. Cross-read
against `archive/0.7.0-comparison-report.md` (prototype `bc2bdf2`), which flagged the
same idea from the other side.

| area | prototype (f286079, `js/`) | current (root files) | verdict |
|---|---|---|---|
| board / moves | `Board` cell-object grid, `ringSlots()` rebuilt + pose per move, corner flips walked by index | precomputed `RING_CELLS` + scratch `permuteRing`, closed-form `crossesMarked` corner rule | current wins — allocation-free, same outcome |
| trace | `Optics.trace` full tracer | packed `Int32Array` queue, enqueue-time visited dedup, persistent buffers | current wins |
| scoring | `groups` (cell + need + exact) | `contract` (requirements + quota + forbidOutside) + progress + discovery history | current wins — hidden targets, replay-friendly |
| generation | continuous `difficulty` 0..1 → `profile()` blends tier params (rings/depth/groups/size/need/exact) | discrete band 0/1/2 → quota/exact policy + band scramble depth + replay-verified witness + preset fallback | **pickup** |
| difficulty signal | `difficultyScore` forward heuristic **and** `par()` BFS true-par (min moves over reachable ring × laser states) | none — `BAND_DEPTH` is "an average, not a difficulty guarantee" (comment in `generate.js`) | **pickup** |
| UI / visuals | single panel, hover preview, range 0..100 difficulty | hints, rim items (0.6), angular drag, solution preview | current wins |

**The one real pickup — a measured, continuous difficulty dial.** Both prototypes
converge on it, each contributing half:

- f286079 shows the **forward** half: a continuous slider blends generation parameters
  (`Generate.profile` interpolates rings/depth/groups/size/need/exact between tiers) and
  then **measures** the result — `difficultyScore` (heuristic) and `par()` (BFS over
  reachable ring-state × laser-column states, returning minimum moves to solve).
- `bc2bdf2` (`archive/0.7.0-comparison-report.md`) shows the **selection** half:
  `sampleWinRate` Monte-Carlo random walks (64 × 20) score candidates against a target
  win rate from a continuous slider, best of 8, using a **separate scoring RNG stream**
  (`seed ^ 0x9e3779b9`) so sampling never perturbs generation.

The current band slider only *labels* a quota/color policy (findings 0.5); it never
measures difficulty. The two prototypes together give a complete, low-risk shape to adopt
on top of the existing replay-verify + preset backbone — plan it as `0.8.0-plan.md`.

**Other notes (not pickups):** f286079's `experiments/difficulty.js` + `compare.js`
measurement harness (sweep slider × mode, diff two logs by key, flag |Δ|>5%) is exactly
the discipline the 0.4 plan asked for ("shortest depth on a bounded search subset") and is
worth porting as-is. Its hover-preview and single-panel UI are subsumed by the current
preview + rim work.
